## Product boundary

Personal Context is the independent, read-only runtime in the two-product
system:

```text
reviewed Markdown → derived local index → bounded MCP context → coding agent
```

- It works with an Obsidian vault or any ordinary Markdown folder.
- Markdown, frontmatter, and wikilinks are the only contract with Knowledge
  Sync.
- It does not read Obsidian plugin state or require Knowledge Sync.
- It does not write into a knowledge folder or code repository.
- Credentials, private evaluation inputs, raw model outputs, and expected
  labels never enter Git, the npm package, the production index, or MCP
  responses.
- Repository rules and the user's current instruction take precedence over
  retrieved personal precedent.

## Private evaluation assets

Private manifests are intentionally absent from the repository. Move them to
the new machine through an encrypted, non-Git channel. Keep the directory mode
at `700` and each manifest at `600`. Verify both frozen SHA-256 values against
the owner-only Vault record before any run.

Never paste a private case, expected label, required element, forbidden
artifact, or raw model output into this repository, a production Vault note, a
prompt transcript intended for Git, or a public issue.

Before invoking a model, use the runner's `--validate-only` mode with explicit
paths, the frozen SHA, an exact model identifier, and an exact reasoning effort.
The knowledge root, source repository, and run output root must not overlap.

```bash
npm run eval:private -- \
  --manifest <private-manifest> \
  --expected-sha <frozen-sha256> \
  --store <knowledge-root> \
  --output <private-run-root> \
  --runner-revision <exact-full-git-object-id> \
  --model <exact-model-id> \
  --reasoning-effort <exact-effort> \
  --conditions A,B,C \
  --validate-only
```

If preflight succeeds, remove only `--validate-only` to create an immutable
run. Use the same source revision, model, parameters, and harness for all
conditions. Preserve every attempt rather than replacing a failed output.
The declared full runner revision must match the checked-out clean evaluation
sources, and A/B/C must run together. A completed attempt writes an owner-only
condition-blinded packet under `blind-review/packet.json`; its condition key and
withheld mechanical evaluation remain separate in `evaluation.json`.
